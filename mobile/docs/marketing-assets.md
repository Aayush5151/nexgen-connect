# Marketing assets brief

**Status:** Out of scope for in-app design. This doc tracks the photographic / cinematic assets that the v15 BP simulations call for, which are deck-slide territory, not in-app surfaces.

Build Prompt B5 confirmation: "No photographs in the app. Document deck-slide asset slots in marketing-assets.md."

---

## Assets needed (deck slides only)

### v15 BP §3.7 Pune → Dublin simulation

Six-slide cinematic of a Pune student arriving at UCD: airport, dorm room, sub-circle introduction, the September 1 view, week-2 in-person meet, week-4 first-mover-call commitment landed.

**Photographer:** consent-licensed images of real Indian students. Founder-commissioned shoot with model release per L4 brand promise. NEVER stock photography.

**Use:** investor deck §3.7, founder all-hands, recruiting site.

### v15 BP §3.7a Mumbai → Galway women-only simulation

Same six-slide structure, but for a Mumbai woman arriving at University of Galway. Highlights the women-only sub-thread auto-spawn moment and the first-mover founder-call commitment.

**Photographer:** same constraints as §3.7. **Critical:** the consent + framing must match the safety-shape narrative — no exploitative imagery, no "alone in a strange place" tropes that contradict the product promise.

**Use:** investor deck §3.7a.

---

## Assets NOT in scope

- Founder photo (handled separately, founder's call).
- App-store screenshots (generated from the actual app at TestFlight time).
- Press kit imagery (built later by founder + content lead).

---

## Why this is in mobile/docs/

The build prompt §Per-screen design pass mentions these simulations as "deck slides" — but the mobile screens that *implement* the simulated journey (O5 corridor preview → CH1 unlocked corridor → CH6 hometown crew → first-mover modal flow) must feel cinematic without these photos. This doc exists so a designer or contractor reading the mobile code path knows where photographic assets are *not* used and where they *would* be used (deck-slide context).
